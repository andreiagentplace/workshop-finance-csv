# Prompt

Улучши существующее React + Vite приложение для анализа банковских CSV-выписок.

Контекст:
У нас уже есть рабочая первая версия сервиса. Она умеет загружать CSV-файл, считать доходы, расходы, баланс, категории, топ-5 расходов и показывать таблицу транзакций.

Проблема:
Сейчас сервис работает только с простым учебным форматом:

date,description,amount,currency

Но реальные банковские CSV-файлы могут иметь:

- разные названия колонок;
- разделитель запятая, точка с запятой или tab;
- суммы с десятичной точкой или запятой;
- кодировку UTF-8 или Windows-1250;
- английские, польские или русские названия колонок;
- дополнительные пустые колонки;
- служебные или лишние колонки;
- описание операции может называться не только “opis operacji”, но и “opis transakcji”.

Задача:
Сделай вторую версию сервиса более устойчивой к разным CSV-форматам.

Добавь:

1. Автоматическое определение разделителя:

- запятая;
- точка с запятой;
- tab.

2. Поддержку сумм:

- -45.90;
- -45,90;
- 1 200,50;
- 1200.50.

3. Автоматическое определение кодировки:

- UTF-8;
- Windows-1250.

4. Нормализацию заголовков колонок:

- убрать лишние пробелы;
- привести к нижнему регистру;
- убрать BOM-символ, если он есть;
- корректно читать польские и русские символы.

5. Распознавание колонок на разных языках.

Дата:

- date;
- data;
- data operacji;
- transaction date;
- дата.

Описание:

- description;
- opis;
- opis operacji;
- opis transakcji;
- merchant;
- details;
- описание.

Сумма:

- amount;
- kwota;
- kwota operacji;
- value;
- suma;
- сумма.

Валюта:

- currency;
- waluta;
- curr;
- ccy;
- валюта.

6. Дополнительная устойчивость:

- если в CSV есть лишние пустые колонки — игнорировать их;
- если в CSV есть дополнительные неизвестные колонки — не считать это ошибкой;
- если после основной колонки описания есть дополнительные текстовые поля, можно добавить их к описанию операции;
- если валюта не найдена, не ломать приложение: валюта необязательна;
- обязательные колонки: дата, описание, сумма.

7. Если файл не распознан — показать понятную ошибку:

“Файл не удалось обработать. Проверьте формат CSV.”

8. Если колонки найдены, но транзакции не распознаны — показать отдельную ошибку:

“Колонки найдены, но операции не распознаны. Проверьте формат сумм и строк.”

9. Добавить информационный блок на странице:

“Поддерживаемые форматы: CSV с колонками даты, описания и суммы. Разделители: запятая, точка с запятой, tab. Сервис работает с учебными и простыми банковскими CSV-файлами.”

10. Показывать информацию об источнике данных:

- имя файла;
- количество операций;
- распознанный разделитель;
- распознанную кодировку, если возможно.

Ограничения:

- без backend;
- без базы данных;
- без API-ключей;
- всё работает только в браузере;
- CSV-данные не отправляются на сервер;
- React + обычный CSS;
- без TypeScript;
- без Tailwind;
- без сложных библиотек;
- проект должен деплоиться на Vercel.

Важно:
Не меняй общую логику и дизайн первой версии радикально. Это должна быть та же учебная версия, но более устойчивая к реальным CSV-файлам.

Верни полный код только этих файлов:

- src/App.jsx
- src/index.css
- README.md
- PROMPT.md

Для каждого файла сначала напиши путь файла, потом полный код.

Код должен быть готов для прямой замены файлов в GitHub.
Без вступлений, объяснений и технических комментариев. Сразу файлы в zip архиве.
